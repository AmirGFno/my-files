# روبیک‌باز — پلتفرم وب آموزش روبیک

سایت استاتیک، بدون build step و بدون وابستگی بیرونی. فقط `index.html` را باز کن
(یا برای تست محلی: `python3 -m http.server 8000`).

## ساختار

```
web/
├── index.html          پوسته‌ی اپ (topbar، main، footer)
├── css/app.css         توکن‌های طراحی + کامپوننت‌ها (تم روشن/تیره)
├── js/cube-engine.js   مدل مکعب + رندر سه‌بعدی تعاملی (Canvas، بدون کتابخانه)
├── js/app.js           روتر هش + ویوها
├── data/methods.js     محتوا: پازل → روش → گام → شش بخش ثابت
└── fonts/              Vazirmatn (woff2، خودمیزبان)
```

## مسیرها

| مسیر | صفحه |
|---|---|
| `#/` | خانه و فهرست پازل‌ها |
| `#/p/3x3` | روش‌های یک پازل |
| `#/learn/3x3/lbl` | معرفی یک روش + فهرست گام‌ها |
| `#/learn/3x3/lbl/cross` | یک گام (قالب شش‌بخشی) |
| `#/algs` | جست‌وجوی همه‌ی الگوریتم‌ها |

## چطور محتوا اضافه می‌شود

فقط `data/methods.js` را ویرایش کن — هیچ کد جاوااسکریپتی لازم نیست:

```js
{
  id: 'new-step',
  title: 'نام گام',
  goal: 'در پایان این گام چه چیزی حل شده است.',
  why: 'منطق پشت روش.',
  states: [{ label: 'قبل', alg: '', view: 'default' },
           { label: 'بعد', alg: "R U R' U'", view: 'top' }],
  steps: [{ t: 'قدم اول', d: 'توضیح' }],
  algorithms: [{ alg: "F R U R' U' F'", label: 'توضیح کوتاه' }],
  mistakes: ['خطای رایج و راه خروج'],
  alternatives: [{ name: 'تکنیک دیگر', why: 'چرا بهتر است', moves: '۸',
                   difficulty: 3, ref: 'other-step-id', recommended: true }],
}
```

`view` یکی از `default | top | bottom | back | front` است.

`next` (اختیاری) همان الگوریتم همین گام است: دکمه‌ی «اجرای گام» روی همان شکل،
مکعب را با چرخش واقعی لایه‌ها به وضعیت بعدی می‌برد. اگر `next` را جا بگذاری،
شکل فقط یک وضعیت ثابت است.

وضعیت مکعب از `alg` ساخته می‌شود، پس اگر الگوریتم غلط باشد تصویر هم غلط
درمی‌آید. برای همین، الگوریتم همه‌ی شکل‌های گام‌های ۳×۳ از سازنده‌ی
`scratch/gen.js` می‌آید و هر عددش اندازه‌گیری می‌شود (پایین را ببین).

## هر شکل، دو حالت

هر شکل دو حالت دارد:

| حالت | چه وقت | اندازه |
|---|---|---|
| کوچک (پیش‌فرض) | کنار متن گام | ۲۲۰px، سه‌تایی در یک ردیف |
| بزرگ | دکمه‌ی «⤢ بزرگ» | مودال تا ۵۲۰px، با همان مکعب و همان انیمیشن |

کنترل‌های هر شکل: **اجرای گام** (انیمیشن واقعی چرخش لایه)، **↺ برگشت**،
**سرعت ۰٫۵×/۱×/۲×**، **زاویه‌ی دوربین** (سه‌رخ/از بالا/از پایین/از جلو) و
**بزرگ**. با ماوس یا انگشت هم می‌شود مکعب را چرخاند؛ زاویه‌های آماده با
اندازه‌گیریِ سهم هر وجه روی صفحه تنظیم شده‌اند، نه با حدس.

اگر سیستم‌عامل `prefers-reduced-motion` را روشن کرده باشد، چرخش‌ها فوری
اجرا می‌شوند (بدون انیمیشن).

## صحت شکل‌ها (مهم‌ترین تست پروژه)

`scratch/gen.js` وضعیت همه‌ی گام‌ها را می‌سازد و هر ادعا را می‌سنجد:

```bash
node tools/cube/gen.js       # همه‌ی بررسی‌ها باید PASS شوند
```

چیزهایی که بررسی می‌شود:

- شکل هر گام، دقیقاً همان چیزی است که برچسبش می‌گوید (مثلاً شکل «خط زرد» واقعاً
  دو لبه‌ی زرد رو به بالا دارد، نه بیشتر).
- کار گام‌های قبلی دست‌نخورده مانده (لایه‌ی اول، دو لایه، صلیب).
- الگوریتم همان گام، از همان شکل، واقعاً به وضعیت بعدی می‌رسد.
- الگوریتم ذخیره‌شده در `methods.js` با اجرای دوباره همان وضعیت را می‌سازد.

## تست‌های دیگر

```bash
node --check js/app.js && node --check js/cube-engine.js && node --check data/methods.js
node tools/cube/viewtest.js      # هندسه و انیمیشن رندر (بدون مرورگر): ۲۷ استیکر، چرخش واقعی، زوایا
node tools/cube/geom.js          # سهم هر وجه در هر زاویه‌ی دوربین + نبود هم‌پوشانی
node tools/cube/datacheck.js     # لینت محتوا: لینک مرده، گام ناقص، شناسه‌ی تکراری
node tools/cube/scenes-shot.js   # شیت PNG همه‌ی شکل‌ها، برای بازبینی چشمی
node tools/cube/shot.js          # رندر PNG یک مکعب در چهار زاویه/میانه‌ی حرکت
```

## وضعیت محتوا

- **۳×۳ / لایه‌به‌لایه**: ۷ گام کامل (هدف، چرا، قدم‌ها، الگوریتم، خطاها، جایگزین‌ها)
- **۳×۳ / پتروس، ZZ، CFOP**: اسکلت گام‌ها آماده، متن در نوبت
- **۲×۲**: لایه‌به‌لایه، اورتگا، CLL — در برنامه
- **بقیه‌ی پازل‌ها**: فقط کارت معرفی

## ایده‌های بعدی

- ذخیره‌ی پیشرفت هر گام در `localStorage`
- حالت تمرین: الگوریتم را از حافظه بزن و اپ درستی‌اش را چک کند
- تایمر و شمارش حرکت برای هر روش
- استاتیک‌سازی همین محتوا به PDF (موتور چاپ در `book/tools` موجود است)
