# کتاب آموزش حل مکعب روبیک — جلد اول

نمونه‌ی اولیه (Sample) برای تأیید سبک، ساختار و موتور تصویرسازی.

فایل خروجی: `out/sample-pages.pdf` — سه صفحه‌ی نمونه:

1. **از کجا شروع کنم؟** — سه مسیر رنگی، مسیر خواندن، و اعلام اینکه هر صفحه‌ی گام چه بخش‌هایی دارد
2. **یک صفحه‌ی گام** — با قالب ثابت شش‌بخشی: ۱ هدف · ۲ چرا این‌جوری · ۳ قدم‌ها · ۴ الگوریتم · ۵ اگر گیر کردی · ۶ جایگزین‌ها
3. **کارگاه روش‌های جایگزین** — یک ردیف برای هر گام، با ستون‌های مشخص و ارجاع به صفحه‌ی توضیح کامل

## اجرا

```bash
cd book/tools
python3 pages.py         # -> ../out/sample-pages.pdf  (+ گزارش خطای چیدمان)
```

اگر خروجی شامل `LAYOUT:` بود، یعنی یک متن از حاشیه‌ی صفحه بیرون زده؛ باید صفر باشد.

پیش‌نیاز: `pip install reportlab arabic-reshaper python-bidi fonttools`
(برای پیش‌نمایش تصویری: `pillow pypdfium2`)

## ساختار کد

| فایل | کار |
|---|---|
| `cube3d.py` | موتور واقعی مکعب ۳×۳: وضعیت هر استیکر، ضرب ماتریس چرخش، پارس نت‌نویسی (`R U R' U2 …`). هیچ تصویری «نقاشی» نیست؛ همه از وضعیت شبیه‌سازی‌شده ساخته می‌شود |
| `render.py` | رندر وکتور: دوربین اورتوگرافیک، حذف وجه پشتی، سایه، هایلایت؛ خروجی PDF و SVG از یک منبع هندسی + نقشه‌ی تخت وجه ۳×۳ |
| `rtl.py` | الگوریتم دوجهته + شکل‌دهی حروف فارسی؛ الگوریتم‌ها (مثل `(R U R' U')`) به‌صورت یک واحد LTR حفظ می‌شوند |
| `typo.py` | لایه‌ی تایپوگرافی: شکستن سطر، تراز راست، اعداد فارسی، فاصله‌گذاری الگوریتم‌ها |
| `design.py` | سیستم طراحی: صفحه، رنگ‌بندی سطح‌ها (مبتدی/متوسط/حرفه‌ای)، کارت، کال‌اوت، جدول |
| `scenes.py` | وضعیت‌های مکعب مورد استفاده، هر کدام با تست ویژگی (مثلاً «دیزی واقعاً دیزی است؟») |
| `pages.py` | همین سه صفحه، و قالب ثابت «صفحه‌ی گام» که کل کتاب رویش ساخته می‌شود |

فونت: Vazirmatn (SIL Open Font License) در `fonts/`.

## تست‌های صحت

```
R U R' U' × ۶ = مکعب حل‌شده      ✅
T-perm × ۲   = مکعب حل‌شده      ✅
x × ۴        = مکعب حل‌شده      ✅
شبکه‌ی «دیزی»: مرکز زرد + چهار لبه‌ی سفید رو به بالا، چهار گوشه زرد   ✅
```

## تصمیم‌های قفل‌شده

- جلد اول: **۳×۳ و ۲×۲** — فعلاً تمرکز روی ۳×۳
- ۳×۳ با **۴ روش**: لایه‌به‌لایه (مبتدی) · پتروس (متوسط) · ZZ (متوسط) · CFOP (حرفه‌ای)
- «روش جایگزین» = **چند تکنیک برای همان مرحله**، نه روش کامل دیگر
- توضیح کامل جایگزین‌ها: **یک بخش واحد** در پایان بخش ۳×۳
- هر ارجاع «← ص ۲۲» با **شناسه‌ی یکتا** ساخته می‌شود و شماره‌ی صفحه در زمان ساخت تزریق می‌شود (هیچ شماره‌ای دستی تایپ نمی‌شود)
- تصاویر: رندر واقع‌گرا برای شروع فصل + دیاگرام تخت وکتور برای مراحل

## قواعد چیدمان که در این نسخه قفل شدند

- **ترتیب خواندن از راست**: هر ردیف کارت یا ستون، از راست به چپ خوانده می‌شود. شکل‌ها هم به همان ترتیب‌اند (شروع → دیزی → صلیب).
- **شماره‌ی فولیو** همیشه در لبه‌ی بیرونی (چپِ صفحه) و **تیتر جاری** فقط یک خط وسط‌بالا.
- **«کجای روش هستی؟»**: هر صفحه‌ی گام یک نوار پیشرفت ۷ مرحله‌ای دارد؛ قدم فعلی توپر است.
- **ستون‌ها با عرض اندازه‌گیری‌شده**: عرض ستون از قبل حساب می‌شود، پس متن هرگز از کادر بیرون نمی‌زند.
- **پرانتز و گیومه** با آینه‌سازی یونیکد (L4) درست می‌شوند؛ خروجی با `bidi-js` به‌عنوان مرجع مقایسه شده است.
- **اعداد مستقل** (مثل «۱۲–۱۶» یا «ص ۴۴») بدون بازآرایی دوجهته چاپ می‌شوند تا برعکس نشوند.

## چطور جلوی خرابی چیدمان گرفته می‌شود

- `typo.set_page()` / `typo.report()` هر متنی را که چاپ می‌شود ثبت می‌کند؛ `Doc.check()` در پایان
  بررسی می‌کند هیچ متنی از حاشیه بیرون نزده باشد.
- عرض ستون‌ها همیشه از قبل حساب می‌شود (`cols`, `table`) — هیچ آفست دستی‌ای در کد نیست.
- عنوان‌ها با `typo.fit_size()` خودشان را تا جا شدن کوچک می‌کنند.
- ارتفاع کال‌اوت‌ها از روی تعداد سطرهای واقعی متن حساب می‌شود، نه با عدد ثابت.

## تست‌های صحت تصویر

- `is_daisy()` و `is_cross()` سخت‌گیرند: هر چهار لبه باید رنگ درست داشته باشند و رنگ کنارشان با
  مرکز خودش یکی باشد. (نسخه‌ی قبلی این تست باگ داشت و حالت غلط را تأیید می‌کرد.)
- حالت‌های استفاده‌شده: `R2 L2 F2 B2` (دیزی) و `R2 L2 F2 B2 F2 R2 B2 L2` (صلیب روی D).
